Kafka GitOps v0.4.1 brings a compact PLAN and consistent PLAN/APPLY reports.
Detailed output focuses on changes, warnings and blockers. `--verbose` retains
INFO and `NO_CHANGE`. SUMMARY shows planned work and recorded APPLY outcomes,
including no-ops, partial changes, blocked work and unknown results.

- **QA-001** counts ACL deletions confirmed by Kafka. Reapplying an absent ACL deletion is a no-op.
- **QA-002** blocks stale partition plans before submission and preserves UNKNOWN for unconfirmed writes.
- **QA-003** verifies PLAN and APPLY in the external IntegrationSpec suite with stable output paths and transcript comparisons.
- **QA-004** bounds RF-decrease verification by one monotonic deadline and allows the ISR to settle without resubmitting the reassignment.

Independent Final QA Round 3 passed 1,153 JVM tests and external IntegrationSpec
on Java 21 (76/76 Windows, 76/76 Linux). Local live scenarios passed on Apache
Kafka 3.2.3, 3.7.1 and 4.4.0 (ELR level 1), and Confluent cp-kafka 7.9.11
(SASL/PLAIN and ACL enforcement). Confluent testing covered RF 4 → 6 across
three racks. ADS, Kerberos, TLS and OAuth were outside the live test matrix.

**Requires Java 21.** The universal JAR includes Kafka Client 4.4.0. Dependency
versions, read-only planning, RF safety checks and credential redaction are
preserved. Verify downloads with `SHA256SUMS`.
