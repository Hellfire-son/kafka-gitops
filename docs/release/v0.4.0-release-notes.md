## Changes since 0.3.1

Java 21 and Kafka Client 4.4.0, built with Gradle Wrapper 9.9.1 and Shadow 9.6.1.
Runtime dependencies are Jackson 3.3.0 / Annotations 2.23, Logback 1.6.6,
SLF4J 2.0.20, Picocli 4.7.7, SnakeYAML Engine 3.2, LZ4 Java 1.14.0,
Snappy Java 1.1.10.12 and Zstd JNI 1.5.7-26. There are 13 runtime artifacts.

The fork manages topic creation, topic configs, partition increases and
replication-factor increases/decreases. Plans use deterministic assignments,
fresh safety/capability checks and bounded diagnostics. ELR and LastKnownELR
are treated as safety evidence; unknown values are not treated as confirmed
empty sets. Apply verifies current state and completion; acknowledgement alone
does not prove completion. Existing ACL and DESCRIBE semantics are unchanged.

Config files are accepted through `--command-config`. Explicit file properties
win over environment properties, which can fill missing values. No Kafka
environment variables are mandatory. Bootstrap servers must be explicit;
unreadable/malformed properties fail safely. Local YAML validation needs no broker.

Text planning includes diagnostic facts, warnings and blockers. Executable JSON
contains operations with their required context; a blocked text preview is not
exported as an executable plan. Existing compatible plans remain readable;
RF context is validated again at apply. No schema migration is introduced by
the release preparation changes.

## Migration and safe usage

**RF is now included in plan by default.** To keep older automation from
managing RF drift, use `--no-manage-replication`. The old `--manage-replication`
flag remains a deprecated compatibility alias. Opposite flags together fail.

`plan` reads Kafka state and never applies the operations. Only an explicit
`apply` changes resources. Decreases appear in the plan, but execution requires
a fresh `apply --allow-replication-decrease`. Global `--no-delete` forbids a
decrease even with that permission. Partition decreases are unsupported.
`BROKER_ONLY` rack policy explicitly accepts the loss of rack protection;
use the default rack-aware policy unless that risk is intended.

```bash
java -jar kafka-gitops-all.jar --command-config client.properties -f desired.yaml validate
java -jar kafka-gitops-all.jar --command-config client.properties -f desired.yaml plan -o plan.json
# Review the plan and fresh safety requirements before this explicit write step:
java -jar kafka-gitops-all.jar --command-config client.properties apply -p plan.json
# Only when an intended RF decrease was reviewed:
java -jar kafka-gitops-all.jar --command-config client.properties apply -p plan.json --allow-replication-decrease
```

Keep `client.properties` and plans outside public Git. Install/build/checksum
instructions are in [installation](../installation.md).

Recorded trials used SHA-256
`04c7fb173b15e87355d94f2f4373bf8d2fef5ee79574342a27f9af1a35c29c4e`.
The release preparation changes version/legal packaging, source notices, docs,
CI and runner path discovery. It does not change RF/ACL business algorithms.
New build/checksum/test evidence is in
[release preparation](v0.4.0-release-preparation.md), outside the packaged JAR's
version-independent legal source inputs. This document is not evidence of new
live trials of the repackaged binary.

Full SASL/TLS/Kerberos/OAuth and ACL enforcement coverage remains incomplete.
Production readiness, all failure/load cases and every native OS/CPU are not
claimed. Old Kafka broker versions are compatibility labs, not a recommendation
for secure production deployment. An updated client does not patch broker CVEs.

## Artifacts, licensing and CI

One universal `kafka-gitops-all.jar` requires Java 21. The optional
`kafka-gitops-0.4.0.zip` contains the POSIX launcher, release notes and legal
materials. The JAR includes `META-INF/licenses/<component>/`,
`META-INF/THIRD-PARTY-NOTICES`, original notices and source-availability details.
Logback is redistributed using its EPL-2.0 option; MIT/BSD/native licenses stay
applicable to their own components. The whole binary is not exclusively Apache-2.0.

Only safe Java/guard CI remains. Release, container, Pages, dependency uploads,
Sonar and Gradle build scans are not automatically executed. Future GitHub
publication is a separate manual stage with a review of Actions/Pages settings.

Known Guava/Jackson advisories inside Gradle remain build-tool warnings and
are not runtime JAR components. No unsupported Gradle-internal overrides were
applied. See [SECURITY.md](../../SECURITY.md) and the preparation report for
current evidence and limits. A private security-reporting destination has not
yet been designated; no invented contact or advisory URL is provided.
