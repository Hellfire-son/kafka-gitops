### Полнота и проверка самого scanner

У этой версии прямой `dir` на `.jar` пропускает его как binary: полученный
«0 findings / 0 bytes» **не использован как evidence чистоты JAR**.
Создан побайтно идентичный ZIP-view с тем же SHA-256; дополнительно явно
разобраны все JAR entries и вложенный launcher JAR из release ZIP.
Искусственный нерабочий sentinel подтвердил detection во вложенных ZIP и
ZIP-представлении JAR; sentinel не входит в release/source files.

Из каждого class file извлечены UTF-8 constant-pool strings, из JNI — ASCII
string views. Проверено 14574 class-pool views и 106 native views, то есть
два представления тех же 7287 классов / 53 JNI ресурсов (JAR и embedded ZIP payload).
Это проверка значимых строк, не доказательство отсутствия произвольного
криптографического материала в любых непрозрачных бинарных данных.

Чтобы стандартные filename allowlists Gitleaks не скрыли wrapper/config files,
выполнен дополнительный scan нейтрально именованных text views всех текущих
eligible source files и всей локальной Git object database: **1286 blobs,
387 commit objects и 22 annotated tag objects**; бинарные wrapper ZIP/class
contents разобраны отдельно. Всего 3593 Git objects, включая tree metadata.
Окончательный поисковый корпус содержит **2574 text views**, включая все
**437 eligible source files**, итоговый отчёт и commit manifest.
Patch counters самого Gitleaks (382/365) не равны количеству всех commit objects:
полнота commit/blob content дополнительно подтверждается object scan.

## 3. Legal bundle и происхождение

В `legal/third-party/<component>/` сохранены тексты из exact runtime/source
artifacts и официальных tagged source archives. `legal/runtime-components.json`
содержит 13 coordinates, runtime/source SHA-256, origin URLs, license choices
и hashes 58 legal resources. Все 26 runtime/source JAR сопоставлены с Maven Central:
22 через SHA-256 sidecars, 4 через SHA-256 полного HTTPS artifact, поскольку
sidecar отсутствовал. Независимая signature certification не заявляется.

В JAR: `META-INF/licenses/<component>/…`, manifest provenance,
`META-INF/licenses/kafka-gitops/LICENSE`, `CHANGES-FROM-UPSTREAM.md`,
`META-INF/THIRD-PARTY-NOTICES` и общий `META-INF/NOTICE` с индексом компонентов.
Каждый оригинальный LICENSE/NOTICE input JAR сохранён побайтно в component path.
Утраченные ранее SLF4J MIT и Jackson notices теперь присутствуют.
Корневой исходный LICENSE не изменён; только его packaged copy нормализована
в LF без добавления завершающей строки. `.gitattributes` сохраняет исходные
third-party legal bytes без автоматической замены line endings.
Packaged provenance и release notes также нормализуются в LF; это устраняет
зависимость output hash от CRLF/LF текущего рабочего дерева и будущего checkout.
Исходные trailing spaces в 14 строках vendor legal texts сохранены вместе с
проверяемыми hashes; Git whitespace attributes ограничены third-party legal
directory. Это не scanner allowlist и не исключение из secret scan.

- Project / Kafka / Jackson / SnakeYAML / Picocli и Java bindings: Apache-2.0
  с сохранением относящихся notices; вложенные Jackson parser licenses сохранены.
- SLF4J: MIT, исходный copyright и полный permission text.
- Logback Classic/Core 1.6.6: выбран **EPL-2.0** из dual EPL/LGPL;
  original dual notice, EPL text, exact sources URLs/SHA-256 и source-availability
  statements находятся в каждом module directory.
- LZ4 Java 1.14.0: binding Apache-2.0; native LZ4 BSD с exact submodule
  c72c7c0ec132ad2ce2fe9fad7b0c728d9faee2fc из официального v1.14.0 tree.
- Snappy Java 1.1.10.12: original LICENSE/NOTICE, Snappy 1.1.10 COPYING/AUTHORS,
  Bitshuffle 0.3.4 MIT и дополнительные native notices. Версии взяты из
  VERSION/build recipe exact binding source, не из одного POM.
- Zstd JNI 1.5.7-26: BSD-2 binding, выбран BSD-3 native option;
  original alternative GPL resource и header credits сохранены без заявления
  о GPL-релицензировании всей программы.
- GCC runtime license/exception texts приложены для соответствующих native
  build recipes; версия источника фиксированного текста исключения не объявлена
  доказательством compiler version каждого prebuilt native binary.

`prepareLegalBundle` использует локальные reviewed resources, без загрузок
лицензий во время сборки. `verifyReleaseArtifact` проверяет graph/JAR hashes,
каждый legal file и каждый original legal input, project copyright/LICENSE,
service providers, JNI bytes, manifest и bytecode. Unique component paths
исключают потерю attribution из-за Shadow EXCLUDE; services имеют INCLUDE и
`mergeServiceFiles`, duplicate output entries запрещены. В ZIP также есть
readable legal tree и LICENSE. Проект не обозначен как исключительно Apache
для всех включённых компонентов. См. [legal README](../../legal/README.md).

Modification comments добавлены в изменённые upstream source/config/docs.
Для JSON/TXT exact-output fixtures и официального wrapper JAR — adjacent
`.NOTICE`, чтобы не менять формат или бинарную подпись. Существующие copyrights
и packages `com.devshawn.*` не удалялись. Новые личные имена/организации не выдуманы.
